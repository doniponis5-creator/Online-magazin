# Спецификация: галерея кухонь и готовые кухни

## Задача

Человек открывает конструктор и видит пустую комнату — с чего начать, непонятно, и многие уходят. А те, кто собрал красивую кухню, не могут её никому показать: проект живёт в одном браузере. Владельцу нужен поток клиентов.

## Решение

В начале конструктора — «Готовые кухни»: 12 проектов разной формы и бюджета, открываются одним нажатием. Любой, кто собрал кухню (покупатель или мастер), может при сохранении поставить её в общую галерею («Всем показать? Да / Нет»). Галерея открыта всем: картинка, оценки, комментарии, техника со ссылками на товары, «Хочу такую же» открывает кухню в конструкторе. Ставить в галерею, оценивать и комментировать — только вошедшим (код в Telegram). Плохое владелец скрывает в панели, как отзывы. Лучшие кухни поднимаются к готовым. У каждой кухни — красивая карточка для Telegram/Instagram.

## Решения по реализации

1. **Хранилище — как у отзывов.** Файлы в томе `/app/data/gallery/` (`kitchens.json` + `images/`), запись через очередь и временный файл с переименованием; память процесса как кэш. Почему: способ уже работает на сервере у отзывов, база данных не нужна, том переживает обновление сайта. До 2000 кухонь; старые скрытые вычищаются первыми.
2. **Кухня в галерее = ссылка на проект + картинка.** Проект хранится строкой `queryFromState` (≤ 4000), как автосохранение; техника и её цены считаются при показе из текущего каталога. Почему: одна правда о проекте, цены всегда свежие, пропавшая модель просто выпадает.
3. **Кто ты — из сессии покупателя** (`currentSession()`: телефон, имя). Телефон хранится только у записи (для «моё», одной оценки, лимитов) и **никогда не уходит в ответ API**; публично — `displayName` и непрозрачный `authorId` (хэш телефона с секретом сайта).
4. **Картинка — кадр 3D из браузера** (`engine.snapshot`), уменьшается в браузере до 1200×750 JPEG ≤ 400 КБ + превью 480×300; сервер проверяет тип по байтам, размер, имя файла строгим шаблоном (как у отзывов). OG-картинка = она же. Без 3D (браузер без WebGL) кнопка «В галерею» недоступна с объяснением.
5. **Готовые кухни — данные в репозитории** (`src/data/kitchen-ready.ts`: id, q, название RU/KY), картинки — в `public/kitchen/ready/`. Их страницы — те же страницы галереи. Почему: владельцу не нужно ничего вводить; меняются правкой одного файла.
6. **Защита от мусора** без предмодерации (решение владельца «видно сразу»): вход обязателен; лимиты по телефону и IP (`tooOften` из `src/lib/assistant/limits.ts`): публикаций ≤ 5 в сутки, комментариев ≤ 1/30 с и ≤ 20/сутки, оценок — без лимита (одна на кухню); в тексте прячутся телефоны (`hideDigits`) и ссылки; жалобы поднимают в панели.
7. **Панель** — как `/panel/reviews`: ключ `ASSISTANT_LOG_KEY`, HTML-ответ, `noindex`.
8. **Страницы** — `src/app/[lang]/kitchen/gallery/` (список) и `[id]` (кухня), серверные, данные читаются из хранилища напрямую, не кешируются статически (галерея живая); метаданные и canonical — как у `/kitchen`.

## Вне рамок

| Требование | Почему не сейчас |

| Приз SBonus за лучшую кухню недели (совет) | нужна правка сервера SBonus через `deploy_shop.sh` — отдельно, по слову владельца |

| Правка опубликованной кухни | публикуется заново как новая; старую автор убирает |
| Ответы на комментарии (ветки) | в брифе — просто комментарии |
| Кабинет мастера, заявки | владелец: «oldin rossa klient orgatvolellik kegin boshlimiza» (бриф, Дополнения) |
