## Что должно заработать

Одно и то же число кухни живёт в одном месте. Сейчас оно переписано руками в 2–4 файлах, и замечание об этом повторилось в пяти тасках (02, 03, 04, 06, 07): поменяй цоколь — и проверка «стиральная выше столешницы», проём посудомойки в спецификации и чертёж разойдутся без единой ошибки. После таска числа для покупателя и мебельщика НЕ меняются — меняется только то, откуда они берутся. Заодно: фактическая высота вытяжки измеряется по поставленной вытяжке, стержневая ручка не шире своего фасада, у сохранения фото один флаг «телефон» с движком.

## Критерии приёмки

- [ ] Цоколь, корпус, столешница, высота низа столешницы (под стиральную/ПММ), проём ПММ, подоконник/верх окна и зазор до потолка, минимумы колонны (160/200), список высоких модулей, «округлить вверх до 5», норма вытяжки (газ/электро), планка углового, деление длинной детали — каждое в одном месте, в лёгком модуле без three.js; все потребители импортируют оттуда; `drawing.ts`/экран больше не делают динамический импорт `build.ts` ради `WINDOW`
- [ ] Числа для покупателя и мебельщика не изменились: все существующие тесты зелёные без правки ожиданий; новый тест сверяет производные (например, низ столешницы = цоколь + корпус; проём ПММ из тех же высот)
- [ ] `Built.hoodOver` записывается один раз по положению поставленного объекта вытяжки (все виды, «камин», остров); тест меряет низ меша вытяжки над столешницей, а не повторяет формулу

- [ ] Флаг «телефон» для сохранения фото берётся у движка (один источник)
- [ ] Два наложения из слепой приёмки на 1440×900: кнопку «Дальше: Размер» не закрывает блок суммы; всплывающая плашка корзины сайта не закрывает размеры в «Для мебельщика» (правка — в зоне кухни, общую плашку не менять); снимки до/после
