# Спецификация: 3D-конструктор кухни — безопасность и телефон

## Задача

Владелец магазина открыл конструктор на iPhone. Кнопка «3D» над картинкой залита синим и
выглядит как залипшая копия, кнопка «⋯» ему не видна, режим «на весь экран» показывает только
картинку — стиль и технику в нём не сменить. Инструменты лежат прямо на 3D и мешают крутить
кухню. Он боится, что конкурент скопирует конструктор, и хочет, чтобы конструктор сам
подстраивался под слабый телефон и сильный компьютер.

## Решение

На телефоне 3D остаётся прилипшим сверху, но **на самой картинке — только верхний ряд**
(отменить/вернуть слева, Фото · Ещё · во весь экран справа). Переключатель видов и кнопка
консультанта уходят с картинки в отдельную полосу под ней. Выбранный вид читается как
вкладка, а не как нажатая синяя кнопка. «⋯» получает слово «Ещё», а его лист всегда поверх
нижнего меню сайта. В режиме «на весь экран» на телефоне снизу остаются вкладки шагов, а
настройки выезжают листом поверх 3D — кухню можно собирать целиком, не выходя из полного
экрана. Движок 3D сам снижает чёткость в движении, если кадры идут медленно, и не тратит
силы телефона на то, чего там не видно. Сайт нельзя вставить в чужой сайт рамкой, прокси
фото отдаёт только фото своего каталога.

## Решения по реализации

- **Заголовки безопасности — в `next.config.ts` (`headers()`), не в nginx.** Почему: сайт
  обновляется `update_site.sh`, nginx руками не трогаем; Cloudflare и nginx заголовки
  пропускают. Перед этим убедиться, что сайт нигде не встраивается в `<iframe>` легально
  (панель 1С открывает адреса в браузере, приложение iPhone грузит сайт напрямую).
- **Прокси фото — белый список.** Каталог (`src/data/products.ts`) статичен на момент
  сборки, значит множество допустимых `src` известно: `Set` адресов фото всех товаров.
  Ключ не в множестве → 400 без запроса наружу. Лимит файла 2 МБ, кэш 40.
- **Переключатель видов на телефоне — полоса под холстом внутри `.kp-stage`.** Сцена
  остаётся одним прилипшим блоком; холст получает `height: calc(100% - 40px)`; полоса —
  обычный поток, сплошной фон, слева виды, справа консультант (`html.kp-pinned .assistant`
  позиционируется в полосу). Почему: единственный способ убрать конфликт с 3D — не класть
  кнопки на 3D.
- **Выбранный вид** — стиль iOS segmented: дорожка `rgb(38 50 68 / 8%)`, выбранный —
  белая таблетка с тенью и цветом `midnight-ink`. Кобальтовую заливку убрать только у
  `.kp-views` на всех экранах (на компьютере тоже читается лучше); остальные `.kp-seg`
  (HD/4K) не трогать. `@media (hover: hover)` вокруг hover; `-webkit-tap-highlight-color:
  transparent` для кнопок `.kp`; на `(pointer: coarse)` у `.kp-seg`/`.kp-toggle`
  `backdrop-filter: none`.
- **Полный экран на телефоне** — новое состояние `fullPanel` (boolean) в `KitchenPlanner`,
  сбрасывается при выходе; классы `kp--full` + `is-panel` на корне. CSS в блоке STACKED:
  `.kp--full .kp-steps { position: fixed; bottom: 0; z-index: 202 }`,
  `.kp--full.is-panel .kp-body { position: fixed; left:0; right:0; bottom: <высота вкладок>;
  max-height: 55dvh; overflow: auto; z-index: 201; border-radius: 18px 18px 0 0 }`;
  без `is-panel` тело панели скрыто. Итог с корзиной внутри тела панели остаётся.
- **Губернатор кадров в `engine.ts`** — измерение `performance.now()` между кадрами
  только пока идёт взаимодействие (OrbitControls `change`/drag); влияет только на
  `motionRatio`; `fineRatio` (покой) не трогает. Никаких новых настроек для покупателя.
- **Названия видов не меняем** («3D» остаётся): владелец так зовёт кнопку.
- **Что не меняем**: адресную схему ссылок, `layout.ts`, `build.ts`, PDF, тексты
  спецификации; desktop-раскладку; `touch-action: none` на холсте.
