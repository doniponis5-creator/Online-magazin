# Спецификация: пакет мастера — раскрой в Excel, кромка, листы, смета

## Задача

Мебельщику конструктор даёт чертёж и таблицы, но работать по ним он всё равно садится вручную: переписывает детали в Excel для пильного центра, считает кромку, прикидывает, сколько листов ЛДСП купить, и отдельно считает цену клиенту. Владелец хочет, чтобы конструктором пользовались все мастера.

## Решение

В блоке «Для мебельщика» появляется «Мастеру»: одна кнопка отдаёт раскрой в Excel для распила (детали с кромкой по сторонам, текстурой, материалом), рядом видно, сколько листов ЛДСП/ХДФ нужно и сколько метров кромки; мастер один раз вводит свои цены и данные — и получает для клиента PDF-смету со своим именем и телефоном. Без регистрации, на телефоне, RU/KY.

## Решения по реализации

1. **Без новых пакетов.** `.xlsx` пишется своим кодом: SpreadsheetML в zip «без сжатия» (store) — ~150 строк, как PDF уже пишется своим `pdfFile`. Почему: пакеты не ставим, файл маленький.
2. **Данные раскроя — из той же спецификации.** `cutting.ts` строит детали из `SpecData` (`cutList`, `frontList`, `topList`, `hardware`) + материал/цвет из выбранной отделки; никаких новых размеров — числа мебельщику не расходятся с чертежом.
3. **Раскладка — гильотина по полосам** (first-fit decreasing), по материалу+цвету+толщине отдельно. Почему: пилы делают только гильотинные резы; оптимальнее не нужно — пильный центр всё равно переоптимизирует, мастеру важно число листов.
4. **Цены мастера — в браузере** (`kp-master`), формат с версией; кабинет и перенос между устройствами — пакет 2.
5. **Материал фасада** берётся из каталога отделки (`finishes.ts`): ламинат ЛДСП — из листа (2 мм кромка); остальное — «в цех фасадов».
6. **Текстура** — у декоров «под дерево» из каталога отделки; корпус по умолчанию белый — без текстуры.
7. **Тексты** — только через `texts.ts`, RU/KY; термины «Духовка», «Варочная панель».

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `src/lib/kitchen/cutting.ts` *(новый)* | детали, кромка, раскладка по листам | `cutParts(spec: SpecData, look: CutLook): CutPart[]`, `CutPart = {id, name, material: {kind:'ldsp'|'hdf'|'mdf', label, color, thick}, length, width, count, grain: boolean, edges: {l1,l2,w1,w2: 0|0.4|1|2}, note?}`; `edgeTotals(parts): {thick, meters}[]` (с запасом 10%); `nest(parts, opts?: {sheet?: {L,W}, kerf?, trim?}): NestResult[]` = `{material, sheetL, sheetW, sheets: {placements: {id, x, y, l, w, rotated}[]}[], waste: number, oversize: string[]}` | алгоритм полос |

| `src/lib/kitchen/master.ts` *(новый)* | цены и данные мастера, смета | `MasterData`, `loadMaster(): MasterData`, `saveMaster(d)`, `estimate(parts, nest, spec, items, prices): {rows: EstimateRow[], total, missing: string[]}` | формат хранения |
| `src/components/kitchen/pdfSheet.ts` | PDF | + `estimateSheet(data)` (смета клиенту) | вёрстка |

**Швы для тестов:** `cutParts`, `edgeTotals`, `nest`, `xlsx` (разбор обратно: zip-структура, XML листов), `cutWorkbook`, `estimate`, `loadMaster`/`saveMaster`.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R07 — кабинет мастера, проекты клиентов, бонус через SBonus | пакет 2 — следующий прогон, по порядку владельца «1 кегин 2» |
| Присадка, DXF для станка | риск ошибки на станке; мастеру хватает Excel для распила (решение из `audit-pro.md` §4) |
| Точная подстройка под конкретный пильный центр | нет образца файла; колонки меняются в одном месте (`cutExcel.ts`) |
| Узбекский язык интерфейса | сайт двуязычный RU/KY; узбекского в брифе как требования нет |

## Открытые места

- **ASSUMPTION:** формат Excel для распила — общий; нужен образец файла от пильного центра Бишкека, чтобы подогнать колонки.
- Цены мастера по умолчанию пустые — это не заглушка, а решение: цены знает только мастер.
