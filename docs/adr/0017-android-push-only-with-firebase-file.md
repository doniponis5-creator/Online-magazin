## Контекст

Для уведомлений Android-приложению нужен файл Firebase `google-services.json`, а скачать его может только владелец в своём аккаунте Google. Без Firebase плагин уведомлений роняет приложение, когда пытается подписаться.

## Решение

Плагин уведомлений попадает в Android-сборку, только если в проекте лежит `android/app/google-services.json`. Нет файла — сборка точно такая же, как сегодня: без плагина и без кнопки «Уведомления о заказах». Сам файл хранится в репозитории.

## Почему

- **Плагин есть, только если есть файл.** «Файла нет» и «сегодняшняя сборка» здесь одно и то же. Поэтому Android-часть можно доделать и выпускать до того, как владелец заведёт Firebase, и приложение у покупателей не упадёт.
- **Плагин всегда в сборке, а сайт проверяет Firebase перед подпиской.** Отвергнуто: если такая проверка ошибётся, приложение упадёт у покупателя, а не просто спрячет кнопку. Сборка по файлу решает вопрос один раз и заранее.
- **Сначала дождаться файлов от владельца, потом делать Android.** Отвергнуто: приложение, сайт и сервер стояли бы без дела. А так владельцу остаётся одно: положить два файла, а не доделывать задачу.
- **Не хранить `google-services.json` в репозитории, считать его секретом.** Отвергнуто: при правиле «нет файла — нет плагина» сборка на другом компьютере (например, на ПК владельца) молча выйдет без уведомлений. Секрета в файле нет: в нём открытый ключ клиента, который и так лежит в каждой скачанной APK.

## Последствия

- Из одного кода выходят две разные Android-сборки, и сборка не предупредит, если файл забыли: приложение просто выйдет без уведомлений. Перед загрузкой в Google Play надо глазами проверить, что в «Кабинете» есть кнопка «Уведомления о заказах».
- Есть ли плагин, решается при `cap sync`, а не при запуске. Положить файл после синхронизации мало: нужны повторный `cap sync` и новая сборка.
- Тестировать нужно обе ветки: сборку без файла и сборку с учебным файлом.
- Файл Firebase навсегда остаётся в истории git. Если проект Firebase пересоздадут, в репозитории появится новый файл, а старый из истории никуда не денется. Ключ клиента защищают настройками в консоли Google, а не тем, что файл спрятан.
