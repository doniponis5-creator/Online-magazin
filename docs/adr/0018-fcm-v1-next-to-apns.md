## Контекст

На iPhone сервер магазина уже шлёт уведомления напрямую через Apple (APNs), и версия приложения 1.0 только что вышла в App Store. Для Android нужна доставка через Firebase Cloud Messaging (FCM), а места, где сервер сообщает о заказе, не должны знать, какой у покупателя телефон.

## Решение

На Android сервер шлёт сам, по протоколу FCM HTTP v1. Запрос подписывается ключом сервисного аккаунта Firebase и обменивается у Google на короткий токен доступа. Отправка через Apple не меняется. Точка отправки одна — `send()`: она сама выбирает путь по платформе адреса, а её сигнатура остаётся прежней.

## Почему

- **Свой клиент FCM v1 рядом с APNs.** Подпись делает библиотека `cryptography`, которая на сервере уже стоит, так что новых зависимостей нет. Код заказов не меняется: для него по-прежнему есть одна `send()`.
- **Официальная библиотека Firebase Admin для Python.** Отвергнуто: это новая тяжёлая зависимость в контейнере API ради одного вида запроса, а подпись и обмен на токен умеет уже установленная `cryptography`.
- **Старый протокол FCM с «ключом сервера».** Отвергнуто: Google его закрыл, остался только HTTP v1.
- **Слать и на iPhone через FCM, одним путём.** Отвергнуто: для этого Firebase пришлось бы встроить в iPhone-приложение и выпустить новую сборку в App Store. А версия 1.0 только что вышла, и адреса iPhone уже собраны напрямую от Apple. Ломать работающую доставку ради единообразия незачем.
- **Отдельная функция отправки на Android, которую вызывают сами места заказа.** Отвергнуто: каждое такое место пришлось бы править и помнить в нём про две платформы. С одной `send()` про новую платформу знает только модуль отправки.

## Последствия

- На сервере теперь лежит закрытый ключ сервисного аккаунта Google (`FCM_SERVICE_ACCOUNT_B64` в `.env.production`). Кто его украдёт, сможет слать уведомления от имени магазина. Заменить ключ можно только через Firebase и повторный запуск `setup-fcm`.
- Протоколов два, и отказы у них разные: мёртвые адреса Android и Apple распознаются по-своему. За изменениями у Google (формат ответов, версия API) теперь следим сами — библиотеки, которая обновилась бы за нас, нет.
- Правило «сбой FCM не мешает ни заказу, ни iPhone» держится на модуле отправки. Его надо перепроверять при каждой правке этого модуля.
- Колонку адреса расширили до 1024 знаков (миграция `009`). Когда в ней появятся адреса Android, сузить её обратно без потери этих адресов уже не выйдет.
- Если ключа нет, Android молчит без ошибки. Снаружи «забыли положить ключ» выглядит так же, как «покупатель запретил уведомления».
