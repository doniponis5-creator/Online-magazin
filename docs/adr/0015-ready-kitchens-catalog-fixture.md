## Контекст

План предполагал взять технику и картинки для 12 готовых кухонь из локального `catalog.json` — того же файла, что участвует в обычной сборке сайта.

## Решение

Таск 02 показал, что локальный `catalog.json` устарел: в нём нет части нужной техники (холодильники, посудомойки, варочные панели), а синхронизировать его локально нечем. Технику для готовых кухонь и картинки взяли фикстурой с живого сайта, а не из локального файла сборки.

## Почему

- **Продолжать собирать готовые кухни только из локального `catalog.json`.** Отвергнуто: часть техники в нём физически отсутствует (файл не той версии), поэтому 12 готовых кухонь с нужным по спецификации ассортиментом из него просто не набрались бы.
- **Сначала синхронизировать локальный `catalog.json` с 1С или живым сайтом, потом собирать.** Отвергнуто: в рамках этой задачи синхронизировать его локально было нечем — актуальный каталог обновляется из 1С в цикле работы сайта, а не по команде разработчика при сборке готовых кухонь.

## Последствия

- Данные готовых кухонь (`kitchen-ready.ts`) собраны по фикстуре с живого сайта на момент сборки (2026-09-27); если ассортимент или цены живого сайта с тех пор изменились, готовые кухни могут ссылаться на устаревшую технику до следующей ручной сверки.
- Картинки готовых кухонь тоже сняты с живого сайта в тот же момент — обновление внешнего вида требует нового захода и не подтягивается само при обновлении каталога сборки.
- Раз локальный `catalog.json` в сборке признан ненадёжным источником для такой задачи, любая будущая работа, которая тоже собирает данные «из каталога сборки», должна сначала проверить его актуальность, а не полагаться на него молча.
