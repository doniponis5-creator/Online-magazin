# План: «Пустая комната» в PRO (29.09.2026)

**Статус (29.09.2026, PC, не закоммичено — владелец проверяет локально):** этапы 0–3 сделаны.
Сверх плана: «Взять эту кухню» (`roomFromKitchen`) и «Верх над всем низом». Отличия от
плана: окно по-прежнему встаёт над мойкой (своё место окна — этап 4); прилипание в пустой
комнате — `FREE_SNAP` 3 см. Верх таскают в 3D (и на другую стену) — сделано 29.09 по просьбе владельца. Остаток этапа 4
(поставить нажатием в 3D, доборы, своё место окна) — впереди.

Владелец: «2 ни килсак хам яхшиди, биринчи мощный план» — сначала план, потом работа.
Строки — по коммиту `8031cdb`. Режим PRO (`kp-pro`) уже сделан, вход в «Пустую комнату» — из него.

**Главное правило владельца: система не должна сломаться.** Обычный конструктор,
старые ссылки, «Мои варианты», галерея и 12 готовых кухонь работают как сейчас.

## 1. Данные (обратная совместимость)

Одно новое необязательное поле; нет поля — всё как сегодня.

```ts
// types.ts, KitchenState
free?: FreeRoom
export type FreeRoom = {
  corners?: ('start' | 'end')[]                                        // угловой шкаф на концах A
  uppers?: Partial<Record<'A' | 'B' | 'C', { c: number; w: number }[]>> // верх: середина от угла и ширина, см
}
```

- Низ — на уже существующих полях: `arrangement` (какая стена), `at` (середина от угла, как
  `itemPositions` layout.ts:911-921 и `pos` в engine.ts:1188), `cabinets` k1..k999 (ширина
  15–120 и `BaseFront`), `widths`, `heights`, `doorsRight`, `fronts`. В свободном режиме
  `pantries`/`tallOven`/`ovenApart` не читаются — решает наличие ключа в `arrangement`.
- Угловой шкаф — в `free.corners`, не новый `ItemKey`: `ITEM_KEYS` и `ITEM_CODE` не трогаем.
- Ссылка (`share.ts`): только при `state.free` пишутся `er=1` (было `fr=1` — совпадало с холодильником; старые читаются), `fk=s|e|se`, `up=`
  (стены через `.`, шкаф — `(\d{3}|-\d{4})w(\d{2,3})`, не длиннее 400 знаков). Проверка `minA`
  (share.ts:222) — только вне свободного режима.
- Для всех старых записей вывод байт в байт тот же: `kp-last`, `kp-variants`,
  `canonicalQuery` галереи, `READY`. Старый код, открыв ссылку `er=1`, покажет обычную
  кухню с той же техникой — не сломается.

## 2. Раскладка

- Один вход: первая строка `planKitchen` (layout.ts:685) — `if (input.free) return planFree(input, options)`.
  `PlanInput.free?`, `planInputOf` (order.ts:58-89) передаёт дальше — все вызовы получают сами.
- `Plan.free?: true`, `Plan.unplaced?: SlotKind[]`, `Run.cornerAt?: ('start' | 'end')[]`.
- `planFree` — новым разделом в конце `layout.ts` (отдельный файл даст цикл импорта).
  Переиспользует как есть: `upperFor`, `narrowToFiller`, `windowSpot`, `clampWindow`,
  `reachCorner`, `indexOfSlot`, `slotWidth`, `hobMinWidth`, `sizedWidth`.
- Что делает `planFree`:
  1. Геометрия — копия правил (775-807): начало ряда, поворот, длина, комната, остров, окно.
  2. Где можно ставить: A — от 0 до `a` минус угловые модули; B — от `DEPTH` до `b`
     (в координатах ряда `x = L − c − w/2`, как переворот на 752); C — от `DEPTH` до `c`;
     остров — вся длина. Так же ограничивает перетаскивание движок (engine.ts:1185-1186).
  3. Вид и ширина — как `kindOf` (708-735). Модель `null` — ключ пропускаем, слот в `unplaced`.
  4. Место: по `at`, без него — первый свободный промежуток от угла; сортировка по x,
     разводка перекрытий вправо и влево, прилипание только ключей из `snap`; не влезло —
     в `Dropped` с нехваткой `need`.
  5. **Промежуток — это просто отсутствие модуля.** Модуль «пусто» не заводим: он попал бы
     во все `switch` build.ts:577-788 и в `t.modules`.
  6. Духовка: модуль `oven`, потом колонна `tall`, потом под варочной (как 810-825), иначе
     `unplaced`. Вытяжки без варочной — `unplaced`. Варочная под окном — вытяжка в `dropped`,
     как 843-846.
  7. Верх (только стены): сам ставится только над варочной (вытяжка), над углом, над
     холодильником, у колонн (`none`). Шкафы покупателя обрезаются окном, этими местами и
     краями ряда, потом `narrowToFiller`. Своих дверец над низом не добавляем.
  8. `tooWide`, `underCounter`, `hoodHeight`, `stove` — копия 827-863.
- **Не трогать:** `resolveRun`, `fillSegment`, `place`, `mergeFills`, `wallItems`,
  `DEFAULT_ORDER`, `resolveArrangement`, `GLUED`/`companions`, `moveItem`/`stepItem`/
  `nextWall`/`pinCabinet`, `itemGaps`.

## 4. Экран (сначала телефон)

- Вход: в PRO на шаге «Форма» кнопка «Пустая комната». Вопрос «Начать с пустой?»; текущая
  кухня сначала в «Мои варианты» (как `openReady`). Итог: `{shape, размеры, style, picks, free: {}}`.
  Ссылка с `er=1` (и старая `fr=1`) открывается в свободном режиме у любого.
- Новый шаг `modules` после «Размер» — только в свободном режиме (`Step`, `STEPS`, `t.steps`
  RU/KY, `STEP_ICON`).
- `FreePalette.tsx` (новый): стены A/B/C/остров; низ 30/40/45/50/60/80/90, ящики 40/60/80,
  мойка 60/80, варочная, духовка, посудомойка, стиральная, холодильник, колонна, пенал (≤ 2),
  угловой (только угловая и П), верх 30/40/60/80. Нажатие — модуль в первый свободный
  промежуток (или справа от выбранного); места нет — строка «свободно N см».
- Чистые операции — `src/lib/kitchen/free.ts`: `freeAdd`, `freeMove`, `freeNudge`,
  `freeResize`, `freeRemove`, `freeGaps` и то же для верха. Возвращают новое состояние или
  причину отказа; экран применяет через `update` — отмена и повтор работают сами.
- Переиспользуем: выбор (`pickRef`), перетаскивание в движке (`onDown`, `moveDrag`,
  `stopDrag`), «левее/правее» (`nudge`, `startRepeat`, стрелки), ширина (`setWidth` →
  `freeResize`), удаление (`removeCab` → `freeRemove`), «на другую стену» (`toOtherWall`),
  фасады (`setFront`, `doorsRight`) без изменений. Верх — через карточку верхнего шкафа
  (кнопки, без 3D-перетаскивания в первой версии).
- В свободном режиме спрятать: «Вернуть как было», пеналы, духовку в колонне, отдельную
  духовку. `setShape` сохраняет `free: {}`. Пустую комнату в галерею не публиковать (`galleryWhy`).
- Шаг «Техника»: модель выбрана, но на стене её нет — «не стоит на стене — Поставить».

- `kitchen-compat.test.ts` (**этап 0, до любых правок**): снимки `planKitchen` для генератора
  из kitchen-drawing и для `READY`; `queryFromState(stateFromQuery(q))` для `READY` и фикстур;

- `kitchen-free.test.ts`: пустая комната каждой формы (геометрия как у правил, модулей нет,
  без NaN); один холодильник (без столешницы, остальное в `unplaced`, сумма — только он);
  порядок духовки; вытяжка под окном; перекрытия и нехватка; угловой шкаф и `cornerAt`;
  верх, обрезанный окном, вытяжкой и колонной; узкий верх → добор.
- Свойства на **400 случайных пустых комнатах** (`rng` из kitchen-drawing, 10–40 операций

  `makerList` сходится; `cutParts`/`nest`/`estimate` конечные; `checkProject` конечные.
- Ссылки: `fr`/`fk`/`up` туда-обратно, мусор отбрасывается, старые ссылки байт в байт,
  `kp-last`. Заказ: не поставленная техника не в сумме и не в WhatsApp. `kitchen-texts` —

Первая рабочая версия — этапы 0–3. Каждый этап: `npx tsc --noEmit`, `npx vitest run`,
`npx next build --webpack`, проверка в браузере на телефоне и компьютере.

**Риски:** общие помощники `layout.ts` служат обоим путям — правка одного меняет другой
(ловят снимки этапа 0); стена B считается в обратную сторону — легко ошибиться; ссылка
`o=` — до 400 знаков (≈ 50 модулей); свои шкафы до k999; старый кэш сайта откроет ссылку
пустой комнаты как обычную кухню.
