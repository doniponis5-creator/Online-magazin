# ТЗ для PC: уведомления «Скидка» и «Новинка» из 1С по шаблонам

> Написано 27.09.2026 на MacBook (ветка `feature/ios-app`). Делает PC — там стоит 1С.
> Владелец: «1, avtomatic bolmasin ! lekin hamma shablonla tursin shu skidka bolyapti
> yokida shu tovar yangi keldi zakaz bersela boladi dep turaman».
> Т. е.: **не автоматически**; владелец сам отправляет из 1С, а готовые шаблоны
> «на этот товар скидка» / «этот товар поступил, можно заказать» уже стоят.

## 0. Что уже есть (сделано 27.09 на MacBook, в этой ветке)

- iPhone: приложение 1.0 в App Store, сервер в боевом режиме Apple (`APNS_PRODUCTION=1`, владелец переключил 27.09).
- Android: всё готово под Firebase — не хватает только двух файлов от владельца
  (`docs/ANDROID_PUSH_UZ.md`, команда `bash scripts/setup-fcm.sh`).
- Сервер: `shop_push.send(db, phone, title, body, data) -> int` шлёт на все телефоны номера — iPhone через Apple,
  Android через FCM (`integrations/sbonus-server/shop/shop_push.py`, `shop_push_fcm.py`). **Любая отправка — только через `send()`.**
- Напоминание о корзине (1 → 3 → 7 дней, только днём, только с согласия): `shop_cart_rules.py`, `shop_cart_remind.py`,
  таблица `shop_cart_reminders` (миграция `010`), cron `/etc/cron.d/sbonus-cart-remind`.
- Сайт: согласие на напоминания о корзине — карточка в «Кабинете» (`src/components/AccountView.tsx`,
  `GET/POST /api/push/consent`, `src/lib/customer/gateway.ts` → `setCartConsent`/`cartConsent`);
  нажатие на уведомление — `listenPushTaps()` в `src/lib/native/push.ts` (сейчас знает `type: "cart"`).
- Каталог из 1С уже несёт `oldPrice` (старая цена), `isNew` (метка «Нов.»), `hit` — см. `src/data/1c/adapter.ts`.
- Весь договор модулей — `.autopilot/2026-09-27-push-apns-fcm/interfaces.md`.

## 1. Что нужно владельцу (как он это увидит)

В 1С → «Панель сайта» — новая вкладка **«Уведомления»**:

1. Два списка товаров из каталога сайта: **«Со скидкой»** (есть `oldPrice` > цены) и **«Новинки»** (`isNew`).
   Поиск по названию/коду. Можно выбрать и любой другой товар.
2. Выбрал товар → выбрал шаблон → текст заполнился сам, его можно поправить:
   - **Скидка:** заголовок «Скидка на {товар}», текст «Было {старая} сом, стало {цена} сом. Можно заказать в приложении.»
   - **Новинка:** заголовок «Новинка: {товар}», текст «{товар} уже в магазине — можно заказать в приложении.»
   - **Свой текст:** пустые поля (для объявлений без товара).
   Цены — **только из каталога 1С**, ничего не придумывать. Нет старой цены — шаблон «Скидка» недоступен для товара.
3. Справа — как это будет выглядеть на телефоне (заголовок жирным, текст, «S Маркет»), и **сколько человек получит**
   (пробный запрос серверу без отправки).
4. Кнопка **«Отправить»** → подтверждение «Отправить N покупателям?» → результат «Доставлено: N».
5. Внизу — последние отправки (дата, заголовок, сколько доставлено).

**Не автоматически.** Никаких отправок по событию каталога — только кнопкой.

## 2. Правила (решены, не переспрашивать владельца)

- **Только с согласия** (правило Apple 4.5.4 — рекламные уведомления только после явного «да» в интерфейсе приложения
  и с возможностью отказаться). Отдельное согласие «Новинки и скидки» — не то же, что «напоминать о корзине».
  Кто не ответил — не получает.
- **Не больше одной рассылки в сутки** (по Бишкеку). Сервер сам отказывает второй с понятной причиной и временем прошлой.
- **Только днём:** 10:00–20:00 по Бишкеку. Нажали позже — сервер отвечает «отправится в 10:00» и отправляет утром
  (или отказывает — выбери проще, но скажи владельцу в 1С понятно).
- Нажатие на уведомление открывает **страницу товара** (или главную для «Свой текст»).
- Текст — по-русски (как все уведомления). Длина: заголовок ≤ 60, текст ≤ 180 знаков — 1С не даст отправить длиннее.

## 3. Что сделать

### Сервер (`integrations/sbonus-server/shop/`)
- Миграция `011`: согласие «Новинки и скидки» по номеру (`NULL` — не спрашивали) и журнал рассылок
  (когда, тип, товар, заголовок, текст, сколько адресатов, сколько доставлено). Идемпотентно; `deploy_shop.sh` знает о ней.
- `POST /webhook/site/promo-consent` — как `cart-consent` (`{phone, consent?}` → `{ok, consent}`), подпись сайта.
- Для 1С (`router_1c_shop`, подпись 1С как у соседей):
  - `GET /webhook/1c/shop/promo/candidates` — товары со скидкой и новинки из каталога сервера (код, название, цена, старая цена, адрес страницы);
  - `POST /webhook/1c/shop/promo/preview` `{kind, code?, title, body}` → `{recipients, blockedReason?}` (ничего не шлёт);
  - `POST /webhook/1c/shop/promo/send` — то же + отправка через `shop_push.send(..., data={"type": "promo", "url": "/ru/product/<slug>"})`
    в фоне; лимит сутки и тихие часы проверяет сервер, а не 1С;
  - `GET /webhook/1c/shop/promo/history` — последние 20 рассылок.
- Чистые правила (лимит, тихие часы, длины, сборка текста по шаблону) — отдельным модулем без импортов приложения,
  с тестами `uv run python -m unittest …` (образец — `shop_cart_rules.py` + `test_shop_cart_rules.py`).
- `account-delete` стирает и согласие на рассылки.

### Сайт (`src/`)
- «Кабинет»: второй переключатель **«Новинки и скидки»** рядом с напоминанием о корзине (та же карточка-вопрос при первом
  показе, тот же образец `role="switch"`), ru + ky; маршрут и шлюз — по образцу `consent` корзины.
- `listenPushTaps()`: `type: "promo"` → `data.url` (только свои адреса `/ru|ky/...`; язык — из текущего адреса).
- Тесты vitest по образцу `__tests__/push-cart-*.test.ts`.

### 1С (`integrations/1c-online-shop/`)
- «Панель сайта» (`ПанельСайтаМодуль.bsl` + форма): вкладка «Уведомления» по пункту 1. Запросы к серверу — тем же способом,
  что `dashboard` (адрес и ключ из «Настроек заказов»).
- Собрать `build_extension.py ut`, поставить **в тестовую копию** (`manage.py install test`), проверить, потом рабочая
  (`manage.py install prod`, печатать `УСТАНОВИТЬ`, закрыть сеансы 1С).

## 4. Перед выкладкой сервера — исправить (замечания ревью 27.09)

Сервер с FCM и корзиной ещё не выкладывался; эти правки — **до** `deploy_shop.sh`:

1. `shop_push_fcm.py` `classify`: 404 **без** JSON-тела FCM (страница прокси, ошибка пути) сейчас стирает адрес — стирать только
   по `UNREGISTERED`/`NOT_FOUND` в теле ответа; прочие 404 — `fail`. Тест на это.
2. `shop_push.py:191`, `shop_admin.py:343`: в журнал пишется текст исключения SQLAlchemy целиком (там может быть телефон/адрес) —
   только тип ошибки и последние 4 цифры.
3. `scripts/fcm-remote.sh:62–71`: временный файл с `.env.production` и ключом без `trap` — при обрыве ssh останется
   в `/opt/sbonus`. `trap 'rm -f "$TMP"' EXIT INT TERM`.
4. `fcm-remote.sh:36`, `setup-fcm.sh:100`: ключ проверяется как `utf-8-sig`, а сервер (`load_account`) читает строгий `utf-8` —
   файл с BOM получит `FCMOK`, но Android будет молчать. Проверка должна принимать ровно то же, что `load_account`.
5. Миграция `009`: колонку без предела длины (`TEXT`) не сужать до 1024.
6. Тест `send()` в репозитории (подменённые HTTP и БД): android → FCM, ios → Apple, без ключа FCM iPhone всё равно получает,
   на `auth` остальные адреса не трогаются.
7. **Корзина (`shop_cart_remind.py:85–205`) — SQL ни разу не выполнялся** (на Mac нет PostgreSQL/sqlalchemy). До выкладки
   прогнать его хотя бы раз на настоящем PostgreSQL (одноразовая схема или тестовая копия): сброс при изменении корзины,
   повтор того же снимка, отсчёт с момента согласия, пропуск после заказа, счётчик только при доставке.
8. `shop_admin.py:383–385`: стирание корзины при удалении учётной записи сидит в старом `try`, чей журнал пишет исключение
   целиком и говорит «адреса не стёрлись» — у каждой чистки своя строка журнала, только тип ошибки и хвост номера.
   `shop_cart_remind.py:228` — то же для cron (первая строка ошибки asyncpg может содержать значение параметра).
9. `shop_cart_remind.py:187–203`: сначала отправка, потом счётчик — при сбое записи через 30 минут уйдёт дубль. Либо
   помечать строку до отправки, либо прямо написать в комментарии «лучше дубль, чем пропуск».
10. Тест на ветку «повторять до покупки» и `MAX_REMINDERS` (сейчас не покрыты; схема владельца — 1 → 3 → 7, ему не мешает).
11. Предпроверка `deploy_shop.sh:69–71` ходит через внутренние имена (`push.fcm`, `cart.rules`) — импортировать сами модули.

Остальные замечания (мелкие, сайт и Android) — в отчёте прогона `.autopilot/2026-09-27-push-apns-fcm/`.
